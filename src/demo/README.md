# Demo mode

A frontend-only build of the app for portfolio use. No backend or database is
needed: every API call is answered in the browser from dummy JSON data.

```bash
npm run dev:demo     # local demo at http://localhost:5174
npm run build:demo   # static build in dist/ (vercel.json already uses this)
npm run demo:data    # regenerate the dummy data
```

## How it works

- `src/demo/data/<Model>.json` holds the dummy data, one file per Mongoose
  model. The documents are shaped exactly like the MongoDB documents (string ids,
  ISO dates, unpopulated refs). They are generated by
  `scripts/demo-data/generate.mjs`; edit that script, not the JSON.
- The data is written around a fixed anchor date (`_meta.json`). On load, every
  date is shifted so the anchor becomes today, so the demo always looks current.
- `src/demo/handlers/*.js` re-implement the backend's routes over that data,
  using the helpers in `src/demo/core/`. `src/api/axios.js` swaps axios's
  network adapter for this mock when the app is built with `--mode demo`.
- Changes made while browsing (new appointments, payments, etc.) live in memory
  and reset on refresh. Razorpay checkout is simulated, and uploads stay in
  the browser. Some actions (for example PDF exports) show "not available in the demo".
- The demo build removes the Google Ads tag and the canonical link, and sets
  `noindex`. A normal `npm run build` contains none of the demo code or data.

To check a mock endpoint from Node:

```bash
node scripts/demo/request.mjs GET "/appointments/today" --as admin
```
